Webサイトをホーム画面に追加できるようにしたら、PWAの実装は完成でしょうか。

私もOJappを開発する中で、最初はホーム画面に追加できることを重視していました。しかし、PWA LABで実機検証を繰り返したり、Petalで個別のページをアプリとして扱ったりするうちに、追加できることと、使いやすいアプリになることは別の問題だと感じるようになりました。

追加する方法が分かるか。期待したアイコンが並ぶか。押したときに目的のページが開くか。そして、ブラウザとは違う使いやすさがあるか。

**PWAのインストールUXは、ホーム画面に追加する操作だけでなく、次にそのアイコンを押すところまで考えて設計する必要があります。**

## ホーム画面に追加すると何が変わるのか

iPhoneではSafariで目的のページを開き、共有メニューから「ホーム画面に追加」を選びます。AndroidではChromeのメニューから「ホーム画面に追加」や「インストール」を選ぶのが基本です。項目名や操作はOSやブラウザのバージョンによって変わります。

どちらもホーム画面にアイコンが現れますが、そのアイコンが通常のブラウザを開くショートカットなのか、独立した画面で起動するWebアプリなのかによって体験は異なります。

Web App Manifestでは、アプリ名、アイコン、起動先、表示モードなどを指定できます。ユーザーがURLを保存するだけの仕組みとは違い、制作者がホーム画面からの体験を設計できるところが面白いと私は思っています。

## ホーム画面に追加できないときは何を確認するか

「追加できない」という相談には、実はいくつかの異なる問題が含まれています。

- ブラウザのメニューに追加項目が見つからない。
- サイト内のインストールボタンが表示されない、または反応しない。
- アイコンは追加できたが、普通のブラウザで開いてしまう。
- インストール済みなのに期待したページや表示にならない。

まず利用者側では、SNSなどのアプリ内ブラウザではなくSafariやChromeで直接ページを開いてみてください。iPhoneでは画像の共有画面ではなく、Webページ自体の共有メニューを確認します。Androidでは「インストール」という別の項目や、すでに追加済みのアプリも確認します。

制作者側ではHTTPS、Manifestの取得状況、アイコン、起動URL、表示モードなどを順番に確認します。Service Workerがないという理由だけでインストールできないと判断する必要はありません。サイト内の独自ボタンが表示されない場合も、ブラウザのメニューから追加できることがあります。

私はPWAの状態を毎回確認するのが面倒になり、PWAの状態を調べるチェッカーも作りました。設定を書いたことと、その設定が端末で実際に反映されていることは分けて考えた方が、原因を見つけやすくなります。

## インストール後の表示はiPhoneとAndroidで違う

Manifestの`display`には、代表的な値として`standalone`と`fullscreen`があります。

`standalone`は通常のブラウザのアドレスバーなどを省いた独立したアプリ表示を意図した設定です。`fullscreen`はさらに画面全体を使う表示を要求します。ただし、実際にどのUIが残るかは端末やブラウザの実装によります。

PWA LABで私がAndroid Chromeを使って比較したときは、`fullscreen`にすると画面の使い方が明確に変わりました。一方、iPhoneでは同じ設定変更をしても、Androidほど分かりやすい差は見られませんでした。

この違いは、単にアプリらしく見えるかという話ではありません。ブラウザの戻るボタンがなくなるなら、ページ内でどう戻るのか。画面の端まで使うなら、操作ボタンがシステムUIやセーフエリアと重ならないか。表示モードを選ぶことで、必要なUI設計も変わります。

## アイコンを押したら、どのページが開くべきか

私が特にこだわっているのが起動先です。

例えば、ある商品のページや個人のプロフィールをホーム画面に追加したのに、次に開いたらサイトのトップページだったらどうでしょう。利用者はもう一度目的のページを探さなければなりません。

Manifestの`start_url`がサイトのルートに設定されている場合、このような起動になることがあります。利用者がアイコンの起動URLだけを後から自由に変更できるとは限りません。追加し直しても、サイト側の設定が同じなら同じ結果になることがあります。

Petalでは、個人ごとの名刺をホーム画面に追加する仕組みを作っています。開発中にはiPhoneで保存したかったURLと実際の起動先が異なる問題に遭遇し、Manifestの`start_url`を`.`にする設計を試しました。私の構成ではこれが解決につながりました。相対URLはManifestの配信方法や基準URLに依存するため、どのサイトでも同じ値に変えればよいという話ではありません。

サイト全体を一つのアプリとして使うならトップページから始めるのも自然です。特定のページを繰り返し使うなら、そのページから始める方が便利です。どちらを選ぶかは、ユーザーが何を目的にアイコンを置くのかで決めたいところです。

## インストールを案内するタイミング

ホーム画面はユーザー自身の場所です。初めて訪れたサイトからいきなり追加を求められても、まだそこにアイコンを置く理由がありません。

私なら、記事を読み終えたとき、ツールを使って目的を達成したとき、あるいは繰り返し使う機能に出会ったときなど、再訪する意味が生まれた場面を重視します。

インストールボタンを常に見つけられることと、毎回目立つ案内を出すことも別です。必要な人が自分のタイミングで追加できる入口を用意しておく方が、自然な体験になる場合があります。

## Chrome 158で見えてきた新しいインストールUX

Chrome 158のWeb Installでは、対応する環境で別のWebアプリのインストールを案内できるようになりました。HTMLの`<install>`要素やJavaScriptの`navigator.install()`によって、PWA紹介サイトからインストール確認へ進む体験を作れます。

私が実際に比較したところ、外部PWAを対象にした`navigator.install()`では追加の権限確認が表示されましたが、`<install>`ではその確認を挟まずインストール画面が開きました。

さらに、別のPWA紹介サイトでボタンが反応しない現象を調べた際、同じYouTubeの`<install>`コードを自分のテストページに移すと正常に動きました。DevToolsには`style_invalid`が表示され、後にサイトの開発者からダークモードのスタイルが原因だったと報告を受けました。

Manifestだけでなく、ボタンのCSSや表示状態、配置数の制限までインストールUXに関係するという、面白い発見でした。

利用者としては、紹介サイトで見つけたPWAも、提供元やURLを確認し、まずブラウザで使ってみるのがおすすめです。インストールできること自体は安全性の保証ではありません。

## まとめ：追加したくなる理由と、もう一度使いたくなる体験

PWAのインストールを考えるとき、私は追加数だけでなく、その後にアイコンが役立つかを大切にしています。

追加方法が分かりやすく、アイコンから期待したページが開き、端末に合った表示で目的を達成できる。この一連の流れがつながって、初めてホーム画面に置く価値が生まれると思います。

OJapp Tipsでは、ホーム画面への追加方法、インストールできない原因、表示モードの実機比較、起動URLの設計、インストール案内のタイミングなどを個別に検証・解説しています。このページを、利用者と制作者の両方がPWAのインストールと表示UXを理解するための入口にしていきます。
