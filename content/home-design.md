スマホのホーム画面を見ていると、その人が普段何を使っているのか、どんなものが好きなのかが少し分かります。仕事で使うアプリを並べる人もいれば、好きな色で統一する人もいます。

私はOJappを開発する中で、Webサイトもその一部になれるのではないかと考えるようになりました。好きなショップや個人ページ、毎日使うWebツールが、専用のアイコンで並んでいてもいいはずです。

ホーム画面のデザインは、単に見た目をおしゃれにすることではありません。**自分が使いたいものを、自分が見つけやすい形で置くこと**。その視点から、アイコンの作り方とWebアプリの設計を考えてみます。

## 2026年のホーム画面カスタマイズ

iPhoneでは純正機能でアイコンの色味やダーク表示、サイズを調整できるようになりました。Androidでもホームアプリなどによってさまざまなカスタマイズができます。

以前なら外部のアイコン素材を集めて一つずつ設定していたような統一感も、端末の機能だけで出せる場面が増えています。

そこで私が面白いと思っているのは、色や形を変えることよりも、何をホーム画面に置くかという自由です。既製のテーマを選ぶだけでなく、自分に必要な入口を組み合わせる。今後はそこに価値が移っていくのではないかと考えています。これは市場の統計から導いた結論ではなく、ホーム画面向けのツールを作ってきた中での私の見方です。

## アイコンを作ることと設定することは別

好きな写真やイラストをアイコンにするなら、まず正方形の画像を作ります。スマホの写真編集アプリでも、Canvaのようなデザインツールでも構いません。

ただし、画像が完成しても、それだけで既存アプリのアイコンが変わるわけではありません。iPhoneのショートカットでは好きな画像を使った起動用の入口を作れます。Androidではホームアプリや端末の機能によって設定方法が異なります。

Webページの場合は、サイト側が用意するアイコンも選択に関わります。例えばBOOTHやBASEのショップを追加すると、ショップ独自のロゴではなくサービス共通のアイコンが使われることがあります。

OJapp Makerを作った理由の一つは、こうしたWebページに好きな画像と名前を持つ入口を作りたかったからです。元のサイトやネイティブアプリのアイコンを書き換えるのではなく、指定したURLへアクセスするための独自の入口を作るという考え方です。

## ホーム画面で見やすい画像を作る

### 画像サイズと用途を分ける

アイコン、壁紙、ウィジェットは同じスマホ画面に表示されますが、画像の使われ方は違います。

| 用途 | 作成時の目安 |
| --- | --- |
| アイコン | 512×512px以上の正方形を原稿にする |
| 壁紙 | 端末の画面比率を基準にし、時計やアイコンとの重なりを確認する |
| ウィジェット | 使用するウィジェットの表示枠に合わせる |

アイコンの原稿を1024×1024pxで作っておくのも便利です。ただし、そのサイズがすべての端末で必須という意味ではありません。PWA用には必要に応じて192pxや512pxなどの画像を書き出します。

### 余白と形状はOSに任せる部分もある

アイコンを大きく表示したときに綺麗でも、ホーム画面で縮小すると細い線や文字が読めなくなることがあります。ロゴを端まで広げると、Androidの円形などのマスクによって重要な部分が欠けることもあります。

私なら、まず背景を含めた正方形を作り、中央に識別しやすいモチーフを置きます。角丸を画像に焼き込むより、端末側の形状処理を考慮して余白を調整します。

Maskableアイコンでは、中心から画像幅の40%を半径とする円が安全領域です。重要なロゴをその内側に収め、背景は画像全体に広げます。通常のアイコンとmaskable用の画像は、用途に合わせて用意するのが無難です。

## PWAの名前とアイコンはどう決まる？

Web App Manifestでは、ホーム画面などに表示される名前や画像の候補を設定できます。

```json
{
  "name": "My Web Tool",
  "short_name": "My Tool",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png", "purpose": "any" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png", "purpose": "any" },
    { "src": "/icon-maskable.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

`name`はアプリの名前、`short_name`は表示スペースが限られる場所向けの短い名前、`icons`は画像の候補です。実際にどれが使われるかはOSやブラウザによって異なります。iPhoneではHTMLの`apple-touch-icon`が優先される場合もあります。

名前は短ければ何でもいいというわけではありません。同じサイトのページを複数追加するなら、どのページなのか区別できる名前が必要です。アイコンと名前をセットで考えると、ホーム画面から目的のページを探しやすくなります。

## OJappで画像を整える理由

OJappの開発では、縦長や横長の画像をどう正方形に収めるか、背景や余白をどう扱うかを考えてきました。元の画像の比率を無視して引き伸ばすと、せっかくのロゴや写真が崩れてしまいます。

CSSの`object-fit`や`background-size`を考えると分かりやすいのですが、Webページ上の画像を綺麗に表示することと、OSがホーム画面で使う画像を生成することは別です。ページに`border-radius`を書いても、インストール済みアイコンの形を直接変更することはできません。

また、Petalでは個人ごとの名刺をホーム画面の入口にすることを考えてきました。全員が同じPetalのロゴで並ぶより、誰のページなのか画像から分かる方が、この用途には合っています。

これは私が提唱している1P1A（One Page. One App.）にもつながります。サイト全体のロゴだけでなく、ページそのものを識別するアイコンを用意するという発想です。

## 追加済みのアイコンは後から変わるのか

ここは実際に試してみて面白かったところです。OJappのアイコンをiPhoneとAndroidに追加したあと、Manifestの`id`は変えずに画像をOJapp PROへ変更しました。

そのまま1ヶ月間、アプリを開かずに放置しました。結果は両端末とも古いアイコンのまま。その後何度か起動しても変わらず、削除して追加し直すと新しい画像になりました。一方、PCでは起動時に更新案内が表示され、更新操作ができました。

今回の実験だけですべての端末の更新仕様を断定することはできません。ただ、サイトの画像を変更すれば既存ユーザーのホーム画面もすぐ変わる、という前提で運営するのは避けたいと思っています。

季節ごとのアイコンやロゴ変更を考える場合にも、この違いは重要です。Webページの更新とホーム画面の画像の更新は別々に考える必要があります。

## まとめ：ホーム画面に残したくなる入口を作る

私がホーム画面のデザインで大切にしているのは、見た目の統一感だけではありません。小さくても見分けられる画像、目的が伝わる名前、そしてそのアイコンを押す理由です。

Webサイトでも、ページごとに意味のあるアイコンを用意すれば、ユーザーが自分の生活に合わせて入口を選べます。ホーム画面はサイト運営者の広告枠ではなく、ユーザー自身の場所です。そこに置いてもらえるものを作るという視点で、これからもアイコンやホーム画面の仕組みを考えていきたいと思います。
