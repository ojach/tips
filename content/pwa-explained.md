PWA（Progressive Web Apps）とは、Webサイトをスマートフォンのホーム画面に追加し、アプリのように起動・利用できるようにするWeb技術の総称です。App StoreやGoogle Playで配布しなくても、URLから利用できるWebの手軽さと、ホーム画面からワンタップで開けるアプリの便利さを組み合わせられます。

ただし、PWAは「Webサイトをアプリに変換する魔法」ではありません。何をホーム画面の入口にするのか、どの機能を必要とするのかによって、適切な構成は変わります。

この記事では、PWAの基本・仕組み・作り方から、私が実際の開発と検証を通じて整理した **1S1A（One Site. One App.）と1P1A（One Page. One App.）** という設計の考え方まで紹介します。初めて調べる方も、実装を考えている方も、必要な項目から読み進めてください。

## PWAでできること：まず知っておきたい5つの機能

PWAを使うと、Webサイトに次のような体験を追加できます。

- **ホーム画面に追加**：アイコンを置いてワンタップでアクセスできる
- **アプリ風の表示**：対応する環境ではブラウザのアドレスバーを隠して表示できる
- **オフライン対応**：Service Workerなどを使い、通信がないときにも一部を利用できる
- **プッシュ通知**：対応OS・ブラウザと許可条件のもとで通知を送れる
- **用途に合わせた起動**：サイトのトップだけでなく、特定のページを入口にする設計もできる

重要なのは、これらが**すべて必須ではない**ことです。ホーム画面から起動できるシンプルなWebツールを作りたいのか、オフラインでも動く業務アプリを作りたいのかで、必要な実装は変わります。

ホーム画面に追加しただけで通常のブックマークと何が違うのかは、[ホーム画面に追加したWebサイトはアプリ？ブックマーク？](https://tips.ojapp.app/home-screen-website-app-or-bookmark/)で整理しています。

## PWAの仕組み：Manifest・Service Worker・HTTPS

### Web App Manifest：アプリの入口と見た目を決める

Web App Manifestは、ホーム画面に表示する名前、アイコン、起動URL、表示モードなどをブラウザへ伝える設定です。

```json
{
  "name": "My Web App",
  "short_name": "My App",
  "start_url": "/",
  "display": "standalone",
  "icons": [
    { "src": "/icon.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

この例では、ホーム画面から起動したときにサイトのトップページを開くよう指定しています。ただし、`start_url` に何を設定するかは、後述するアプリ設計そのものに関わります。

項目ごとの意味やOSによる違いは、[manifest.jsonの基本｜iPhoneとAndroidで効く項目](https://tips.ojapp.app/pwa-manifest-json-basics/)で詳しく解説しています。

### Service Worker：キャッシュ・オフライン・通知を支える

Service Workerは、Webページとは別に動作し、通信やキャッシュなどを扱えるJavaScriptです。オフライン対応やプッシュ通知などに使われます。

ただし、**ホーム画面への追加を目的とするだけなら、Service Workerが常に必要なわけではありません。** PWAのインストール判定や利用可能な機能はブラウザ・OSによって異なります。

実際の確認結果は[Service Workerは必須？2026年のChromeで検証](https://tips.ojapp.app/pwa-service-worker-required-2026/)にまとめています。

### HTTPS：Webアプリの基本的な前提

Service Workerなどの重要なWeb APIは、原則としてHTTPSのような安全なコンテキストで動作します（開発用のlocalhostなどには例外があります）。公開するPWAではHTTPSを基本に考えましょう。

## PWAの設計で大切なのは「何を1つのアプリにするか」

一般的な解説では、Manifestの書き方が中心になりがちです。しかし実際に作り始めると、もう一つ大切な問いがあります。

**ユーザーがホーム画面に保存したいのは、サイト全体なのか。それとも今見ているページなのか。**

私はこの違いを、1S1Aと1P1Aという2つの設計思想として整理しています。どちらもWeb App Manifestを使った設計であり、優劣ではなく用途の違いです。

### 1S1A（One Site. One App.）：サイト全体を1つの入口に

```json
{
  "start_url": "/",
  "display": "standalone"
}
```

サイトのトップを入口にする設計です。企業サイト、ポータル、サービス全体を一つのアプリとして利用してもらいたい場合に向いています。

```text
ホーム画面
└─ 🏠 サイト
   ├─ 記事
   ├─ 商品
   └─ お問い合わせ
```

### 1P1A（One Page. One App.）：ページそのものを入口に

```json
{
  "start_url": ".",
  "display": "standalone"
}
```

ページ単位でManifestを用意し、現在のページを基準にした起動URLを使う設計です。記事、商品ページ、プロフィール、予約ページ、Webツールなど、個々のページに独立した価値がある場合に向いています。

```text
ホーム画面
├─ 📄 記事A
├─ 🛒 商品ページ
├─ 📅 予約ページ
└─ 🧮 Webツール
```

Webはもともと、検索結果もSNSの共有もブックマークも、ページ単位で扱われてきました。それならホーム画面もページ単位でよいのではないか。この発想が1P1Aの出発点です。

ただし、`start_url: "."` を書くだけで、どんなサイトでも自動的に複数の独立アプリとしてインストールできるわけではありません。Manifestの配信位置、`id`、`scope`、OSの扱いも関係します。

設計思想の背景は[1P1AというPWA設計思想](https://tips.ojapp.app/1p1a-2/)で、サイト単位との違いは[PWAの二極化：1S1Aと1P1A](https://tips.ojapp.app/pwa-1s1a-vs-1p1a/)で掘り下げています。

## PWAの作り方：手動設定から1行スクリプトまで

自分で実装するなら、まずManifestを用意してHTMLから読み込み、必要に応じてService Workerを追加する方法が基本です。ホーム画面に追加した際の表示や起動URLを、実機で確認します。

最初から実装手順を追いたい方は、[PWAの作り方｜manifest.json・Service Worker・ホーム画面対応](https://tips.ojapp.app/how-to-pwa/)が入口になります。

### WordPressならプラグインを使う方法

WordPressでは、PWA対応プラグインを使って設定を簡略化できます。例えばOJapp PWA Marketingは、投稿・固定ページ・WooCommerceの商品ページ向けに、ページごとのManifestやアイコンを生成するためのプラグインです。

[OJapp PWA Marketing](https://ojapp.app/pwa-marketing/)で仕様を確認できます。

### WordPress以外なら、1行でManifestを生成する方法も

OJapp FREEの1P1A用スクリプトなら、例えば次のように導入できます。

```html
<script src="https://ojapp.app/js/ojapp_1p1a.js"></script>
```

必要ならページ名やアイコンを指定します。

```html
<meta name="ojapp:title" content="ページタイトル">
<meta name="ojapp:icon" content="https://example.com/icon.png">
```

Manifestをページごとに手動管理せず、クライアント側で生成する方式です。これはホーム画面アプリ化の入口を簡単にするものであり、オフライン対応などが必要なら別途設計します。

## PWAはどんなサイトに向いている？

サイト全体を何度も訪れてほしいサービスなら1S1Aが自然です。一方、特定のツール、商品、記事、会員向けページなどを繰り返し開いてもらうなら、1P1Aのようなページ単位の入口が便利な場合があります。

重要なのは「PWAだから導入する」のではなく、**ユーザーが次にそのページを開く理由があるか**です。導入の向き不向きは[PWAに向いているサイト・向いていないサイト](https://tips.ojapp.app/pwa-suitable-websites-use-cases/)で、ユーザー側のメリットは[PWAのメリットをユーザー側から考える](https://tips.ojapp.app/pwa-user-benefits/)で紹介しています。

## iPhoneとAndroidで同じように動く？

PWAの基本となるWeb技術は共通でも、ホーム画面への追加方法、アイコンの扱い、表示モード、複数アプリの扱いには違いがあります。特にiPhoneでは、Androidと同じインストール導線を期待しない方が安全です。

iPhone側の仕様や制限を調べたい場合は、[PWA×iPhoneでできること完全ガイド【2026年版】](https://tips.ojapp.app/pwa-ios-capabilities/)を参照してください。

## まとめ：PWAは「追加する技術」であり「入口を設計する技術」でもある

PWAを理解する第一歩は、Webサイトをホーム画面からアプリのように使える仕組みだと知ることです。Manifestは入口と見た目を定義し、Service Workerは必要に応じてオフラインやキャッシュなどを支えます。

そのうえで考えたいのは、**何を一つのアプリとしてホーム画面に置くのか**ということ。サイト全体を入口にする1S1Aと、ページを入口にする1P1Aは、その選択を整理するための考え方です。

まずは使いたい機能と、ユーザーが再び開きたいページを決める。そこからPWAの設計を始めるのが、私の考える一番自然な順番です。
