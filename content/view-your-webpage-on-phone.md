PCで作った`index.html`をブラウザで開けたら、次はスマホでも確認したくなりますよね。

結論からいうと、**スマホで見る方法は「無料で公開する」「同じWi-Fiでプレビューする」「HTMLファイルを送る」の3つ**です。目的によって一番簡単な方法が変わります。

| 方法 | こんな人向け | 公開される？ |
| --- | --- | --- |
| GitHub Pagesなどの無料ホスティング | スマホで何度も見たい・人にも見せたい | はい |
| PCとスマホを同じWi-Fiにつなぐ | 制作中の画面をすぐ確認したい | いいえ（通常はローカルネットワーク内） |
| HTMLファイルを直接送る | とりあえず1枚だけ確認したい | いいえ |

## 方法1：無料で公開してスマホから開く

**URLを使ってスマホで開きたいなら、無料ホスティングがわかりやすい方法です。** 一度公開すれば、PCを閉じていてもスマホからアクセスできます。

代表的なのは[GitHub Pages](https://pages.github.com/)と[Netlify](https://www.netlify.com/)です。どちらも静的なHTMLページの公開に使えます。利用条件や無料枠は変更されることがあるため、登録時に確認してください。

### GitHub Pagesで公開する手順

1. [GitHub](https://github.com/)でアカウントを作成してログインします。
2. 「New repository」から新しいリポジトリを作ります。例として`my-first-page`という名前にします。
3. リポジトリの「Add file」→「Upload files」で、PCの`index.html`をアップロードしてコミットします。
4. 「Settings」→「Pages」を開きます。
5. 「Build and deployment」で「Deploy from a branch」を選び、ブランチを`main`、フォルダを`/(root)`にして保存します。
6. 公開処理が完了したら、Pagesに表示されるURLをスマホのSafariやChromeで開きます。

URLは通常、次のような形になります。

```text
https://ユーザー名.github.io/my-first-page/
```

公開には少し時間がかかることがあります。保存直後に404が表示されたら、Pagesの公開状況を確認してから再度アクセスしてください。

**注意：GitHub Pagesで公開したページは、基本的にインターネット上の誰でも見られます。** パスワードや個人情報、公開したくない画像はアップロードしないでください。リポジトリを非公開にしても、公開Webサイトのアクセス制限になるとは限りません。

### スマホで表示が崩れたら

HTMLの`<head>`に次の指定があるか確認します。

```html
<meta name="viewport" content="width=device-width, initial-scale=1.0">
```

これはスマホの画面幅に合わせてページを表示するための基本設定です。ただし、これだけでデザインが自動的にスマホ対応になるわけではありません。固定幅の要素がある場合はCSSも見直します。

## 方法2：同じWi-FiでPCのページをスマホに表示する

**まだ公開したくない、でも実際のスマホで表示を確認したい。** そんな制作中の確認に便利なのがローカルサーバーです。

PCとスマホを同じネットワークにつなぎ、PCでWebページを配信します。スマホはPCのローカルIPアドレスへアクセスします。

### VS CodeとLive Serverを使う場合

1. PCに[Visual Studio Code](https://code.visualstudio.com/)をインストールします。
2. `index.html`のあるフォルダをVS Codeで開きます。
3. 拡張機能から「Live Server」をインストールします。
4. `index.html`を右クリックし「Open with Live Server」を選びます。
5. Live Serverの設定で、必要に応じてLANからアクセスできるアドレスで待ち受けるようにします。
6. PCのローカルIPアドレスを調べ、スマホのブラウザで`http://192.168.1.10:5500/`のように入力します。

ここでの`192.168.1.10`は例です。**実際には自分のPCのIPアドレスに置き換えます。** `localhost:5500`をスマホに入力しても、それはスマホ自身を指すためPCのページは開けません。

Windowsならコマンドプロンプトの`ipconfig`、Macならネットワーク設定からローカルIPアドレスを確認できます。

### つながらないときの確認ポイント

- PCとスマホが同じWi-Fiまたは相互通信できるネットワークにいるか
- Live Serverが`127.0.0.1`だけで待ち受けていないか
- Windowsファイアウォールなどが接続を遮断していないか
- ゲストWi-Fiの端末間通信制限が有効になっていないか
- ポート番号がLive Serverの表示と一致しているか

ローカルサーバーは**PCが起動し、サーバーが動いている間だけ**利用できます。外部公開とは違います。また、同じネットワーク内のほかの端末からもアクセスできる設定になるため、信頼できるネットワークで使ってください。

Live Serverはファイル変更時の自動リロードにも対応しており、スマホのレイアウトを調整しながら確認する用途に向いています。

## 方法3：HTMLファイルをスマホに直接送る

HTMLが1ファイルだけなら、AirDrop、メール、クラウドストレージなどで`index.html`をスマホへ送る方法もあります。

ただし、**ファイルをタップすれば必ずSafariやChromeで普通のWebサイトとして開ける、というわけではありません。** iPhoneではファイルアプリのプレビューになったり、Androidでもファイル管理アプリやブラウザの制限で表示方法が変わったりします。

また、HTMLから`style.css`や`images/photo.jpg`を読み込んでいる場合、HTMLだけ送ってもそれらのファイルは表示されません。フォルダ構成ごと移す必要があります。

JavaScriptの`fetch()`や一部のブラウザAPIは、`file://`で開くとセキュリティ制限により動作しない場合もあります。 **「ファイルが表示できた」ことと「Webサイトとして正常に動く」ことは別**です。

そのため、この方法は文字と簡単な装飾だけの単一HTMLをざっと確認したい場合に限定して考えるとわかりやすいです。

## どれを選ぶのが一番簡単？

「家族や友達にも見せたい」「URLでいつでも開きたい」なら、GitHub Pagesなどで公開する方法がおすすめです。公開用URLができるので、スマホでブックマークするのも簡単です。

「公開する前にスマホ表示だけ試したい」なら、同じWi-Fiを使ったローカルプレビューが向いています。制作中に何度も修正するなら、こちらの方が効率的でしょう。

「とりあえず1枚のHTMLがどんな見た目か確認したい」だけならファイル送信も選択肢ですが、端末によって開き方が違う点には注意してください。

## まとめ

PCで作ったWebページは、スマホでも無料で確認できます。**公開してURLから開くなら無料ホスティング、制作途中ならローカルWi-Fi、単純なHTMLの確認だけならファイル転送**と覚えておけば十分です。

個人的には、初めて作ったページをスマホで開くなら、公開URLを取得できる方法が一番わかりやすいと思います。PCで開いた`index.html`が、スマホでも同じURLから見られる。それだけで、ローカルのファイルとWebサイトの違いがぐっと実感できるはずです。
