「iPhoneではPWAが終了した」</p>

2024年ごろ、このような情報を見た人も多いかもしれません。

実際、Appleは2024年にEU向けのiOSで**ホーム画面Webアプリ（Home Screen Web Apps）の機能を削除する計画**を一度発表しました。

しかし、この計画はその後撤回されています。

そして2026年現在、iPhoneのPWAは終了していません。

むしろ現在のiOSでは、Webサイトをホーム画面からWebアプリとして起動する仕組みが、以前より広いWebサイトで利用できるようになっています。

では、なぜ「iPhoneのPWAは終了した」という話が広まったのでしょうか。

この記事では、2024年に起きたPWA終了騒動から、現在のiPhone・Safari・ホーム画面Webアプリの状況まで整理します。



## 結論：2026年現在、iPhoneのPWAは終了していない

まず結論から言うと、**iPhoneのPWAやホーム画面Webアプリは終了していません。**

iPhoneでは現在もWebサイトをホーム画面へ追加でき、ホーム画面からWebアプリとして起動できます。

Web App Manifestも引き続き利用でき、アイコンや起動URLなど、ホーム画面Webアプリの動作を設定できます。

さらにService Workerを利用したオフライン対応や、ホーム画面WebアプリからのWeb Pushなどもサポートされています。

つまり、「SafariからPWAが削除された」「WebClipだけになった」という状態ではありません。



## なぜ「iPhoneでPWAが終了する」と言われたのか

この話のきっかけは2024年です。

EUのDigital Markets Act（DMA）への対応に伴い、AppleはiOS 17.4でブラウザエンジンなどの仕組みを変更しました。

その過程でAppleは一度、EU地域において**Home Screen Web Appsの機能を削除する計画**を発表しています。

これにより、ホーム画面へ追加したWebサイトが従来のWebアプリとして動作せず、ブラウザで開くブックマークに近い動作になる可能性がありました。

この発表をきっかけに、

- 「AppleがPWAを廃止する」
- 「iPhoneではPWAが使えなくなる」
- 「SafariのPWAは終了する」

といった情報が広まりました。



## しかしAppleはPWA削除計画を撤回した

ところが、この方針はそのまま実施されたわけではありません。

Appleはその後、Home Screen Web Appsを継続してほしいという要望を受け、EUでも従来の機能を提供し続ける方針へ変更しました。

そのため、正式版のiOS 17.4ではHome Screen Web Appsの機能が継続されています。

つまり2024年に起きた出来事を正確に整理すると、

**「PWAが終了した」のではなく、「EUで終了する計画が一度発表されたが、その後撤回された」**

ということになります。



## その後もiPhoneのWebアプリ機能は追加されている

PWA終了説とは反対に、その後のSafari・WebKitではホーム画面Webアプリ向けの機能も引き続き開発されています。

例えばiPhoneでは、ホーム画面へ追加したWebアプリでWeb Pushを利用できます。

さらに2025年には、Service Workerを必須とせず通知を扱える「Declarative Web Push」もiOS 18.4で追加されました。

少なくとも現在のAppleの動きを見る限り、ホーム画面Webアプリという仕組み自体を廃止する方向には進んでいません。



## iOS 26では「すべてのWebサイト」がWebアプリになった

さらに大きな変化がiOS 26です。

以前のiPhoneでは、ホーム画面からWebアプリとして起動するために、Web App Manifestの`display`や従来のmetaタグなど、Webサイト側の設定が関係していました。

しかしiOS 26では、この仕組みが変更されています。

**ホーム画面へ追加したWebサイトは、デフォルトでWebアプリとして開くようになりました。**

つまり、Webサイト側が従来のPWA設定をしていない場合でも、ユーザーがホーム画面へ追加すればWebアプリとして利用できます。

追加時には「Webアプリとして開く」をオフにして、通常のブラウザで開くホーム画面ブックマークとして保存することもできます。

これは「PWAを終了する」というより、むしろ**ホーム画面Webアプリの入口をすべてのWebサイトへ広げた変更**と考えた方が実態に近いでしょう。



## ではWeb App Manifestはもう不要なのか？

ここは少しややこしいポイントです。

iOS 26では、Webアプリとしてホーム画面から起動するだけなら、従来のようなManifest設定は必須ではなくなりました。

しかし、**Web App Manifestそのものが不要になったわけではありません。**

Manifestを設定することで、例えば次のような情報をWebアプリへ与えることができます。

- アプリ名
- ホーム画面アイコン
- 起動するURL（start_url）
- 表示方法（display）
- アプリとして扱うURL範囲（scope）

Apple自身も、iOS 26の変更について「Web App Manifestのサポートを削除するものではない」と説明しています。

つまり2026年のiPhoneでは、

**Webアプリとして開くだけなら簡単になった。しかし、どんなWebアプリとして動かすかを設計するManifestは今も重要。**

という状態です。



## iPhoneのPWAとAndroidのPWAは同じではない

ここでもう一つ注意したいのが、iPhoneとAndroidでは「PWA」の扱いが完全に同じではないことです。

AndroidのChromeでは、Web App Manifestやインストール条件をもとに、Webアプリとしての扱いが決まるケースがあります。

一方、現在のiPhoneではユーザーがホーム画面へ追加すること自体が、Webアプリ化の入口になっています。

そのため「PWAとはこの条件を満たしたWebサイト」という一つの定義だけで、iPhoneとAndroidの挙動を説明するのは難しくなっています。

OJappのPWA LABでも、同じManifestを使っていてもiPhoneとAndroidで`scope`やアイコン、表示方法などの挙動が異なるケースを実機で確認しています。



## 2026年のPWAは「終了」ではなく形が変わっている

2024年の出来事だけを見ると、「AppleがPWAから撤退する」と感じても不思議ではありませんでした。

しかし、その後の流れを見ると結果は逆でした。

- EUでのHome Screen Web Apps削除計画は撤回
- ホーム画面Webアプリのサポートは継続
- Web Pushなどの機能も継続・拡張
- Web App Manifestも引き続き利用可能
- iOS 26ではすべてのWebサイトをWebアプリとして開ける方向へ拡張

そのため2026年現在、「iPhoneのPWAは終了した」と考えるのは正確ではありません。

むしろ面白いのは、 **「PWAとして作られたWebサイトだけがアプリになる」という境界が薄くなっていること**です。

Webサイトがあり、ユーザーがそれをホーム画面へ置く。

そして必要であれば、開発者がManifestやService Workerを使って、さらにアプリらしい体験を追加する。

iPhoneのホーム画面Webアプリは、そんな方向へ変化しています。



## まとめ：iPhoneのPWAは終わっていない

2024年には、確かにAppleがEUでHome Screen Web Appsを削除する計画を発表しました。

しかしその計画は撤回され、その後もホーム画面Webアプリの機能は継続されています。

そしてiOS 26では、ホーム画面へ追加したWebサイトをデフォルトでWebアプリとして開くという、さらに大きな変更が入りました。

**PWAが終了したのではありません。**

**「どのWebサイトをアプリとして扱うか」という考え方そのものが変わってきています。**

Webとアプリの境界はなくなったわけではありません。

ただ、その境界は以前よりずっと曖昧になっています。
